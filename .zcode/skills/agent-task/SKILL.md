## 0. Правила

Прочитай `README.md` целиком — он обязателен и важнее этой команды там, где с ней расходится. Код сайта — TypeScript strict + React 18 + MobX 6 (`observer` из `mobx-react-lite`) + Vite 6. Тестов и линтера нет: проверка — `npm run build` и живой просмотр.

## 1. Свои ветки и PR — аренда 60 минут

Ты работаешь под **маркером цикла** `<МАРКЕР>` (его передал вызов; одноразовый запуск генерирует свой: `<я>-<4 случайных символа>`). Владение задачей — это ветка `agent/<я>/issue-<N>`, где последний протокольный коммит `claim:`/`adopt:` несёт твой маркер. Метка `agent:<я>` — только аннотация. **Аренда — 60 минут** с последнего коммита ветки или обновления её PR (`gh pr view <N> --json updatedAt`): тише — владельца нет, ветку примет любой экземпляр роли.

Собери свои ветки (с PR и без):

```sh
gh pr list --state open --label agent:<я> --json number,headRefName
git ls-remote --heads origin "refs/heads/agent/<я>/*"
```

Для каждой своей ветки `agent/<я>/issue-<N>` определи владельца и свежесть:

```sh
git fetch origin agent/<я>/issue-N
git log --format=%s FETCH_HEAD | grep -E '^(claim|adopt): ' | grep -oE '\[[^]]+\]' | head -1
git log -1 --format=%cI FETCH_HEAD
```

- **Маркер твой** → веди ветку (правила ниже).
- **Маркер чужой, а последний коммит или `updatedAt` PR свежее 60 минут** → ветку ведёт другой живой экземпляр: не трогай, следующую.
- **Маркера нет (легаси) или тише 60 минут** → прими: `git fetch origin agent/<я>/issue-N`, `git checkout --detach FETCH_HEAD`, `git commit --allow-empty -m "adopt: issue-#<N> [<МАРКЕР>]"`, `git push origin HEAD:refs/heads/agent/<я>/issue-N`, после успеха закрепи локально: `git checkout -B agent/<я>/issue-N`. Пуш отвергнут — её уже повели: отступи, следующую.

Ведёшь ветку — доведи до мержа:

- Ветка отстала от `main` или конфликт → `git fetch && git merge origin/main` (**не** rebase, **не** force-push), разреши конфликт, прогони `npm run build`, запушь.
- CI красный → почини в той же ветке.
- **Перед мержем — прочитай, что тебе велели исправить.** Комментарии PR (`gh pr view <N> --comments`) и задачи (`gh issue view <задача> --comments`). Любая просьба оператора или ведущего фабрики что-то исправить — ревью «**Не мержить до исправления**», подпись «Аудит по протоколу фабрики» с находкой, просто «поправь …» — после которой нет твоего коммита с правкой и ответа в PR, блокирует мерж: исправь в той же ветке, ответь в PR, что и где исправил (или почему не исправляешь — и тогда не мержи, а оставь решение оператору), и только потом мерж. Молча мержить поверх такой просьбы нельзя. Находки, которые ведущий уже вынес в отдельную задачу («Заведено: #N»), — не просьба исправить в этом PR.
- CI зелёный, ветка на текущем `main` и задача ещё открыта → `gh pr merge <N> --merge`. Задачу закрыли — не мержи (см. шаг 5).

- Ветка без PR: есть рабочие коммиты — открой PR (шаг 4); только claim/adopt — реализуй задачу с этой ветки (шаги 3–4).

Отвёл хоть одну ветку — доведи её и **закончи сессию**, новую задачу не бери. Все ветки чужие-свежие → шаг 2.

## 2. Взять одну задачу — захват атомарный

Кандидаты — открытые issues с меткой `task` без метки `agent:*`. Метка `for:<имя>` — рекомендация, а не запрет. Порядок выбора:

1. с меткой `for:<я>`;
2. без метки `for:*`;
3. с меткой `for:<другое имя>` — только если в пунктах 1–2 подходящих нет.

```sh
gh issue list --state open --label task --json number,title,labels
```

**Твой уровень ограничивает выбор.** Прочитай свою строку в таблице «Уровни агентов» в начале `docs/audit-log.md` (её ведёт аудит; нет файла — уровень «обычный»). Уровень «без типов» — не бери задачи с меткой `for:opus` и задачи, цель которых — стор, типы или адаптив, даже если других нет; типы в существующем коде не меняй — только добавляй контент. Уровень «ограниченный» — только тексты и мелкие правки стилей по готовому факту, без `for:opus`. Нет подходящих по уровню — «очередь пуста».

Подходящий — тот, чьи зависимости закрыты. Прочитай тело кандидата (`gh issue view <N>`): строка вида «Зависит от #M: не брать, пока #M открыт» — это зависимость. Если хоть одна из них открыта (`gh issue view <M> --json state --jq .state` → `OPEN`), пропусти кандидата, даже если он первый в списке. Не берись «заодно» и за зависимость: её ведёт другой агент.

Возьми первого подходящего кандидата `<N>` и захвати задачу **атомарным пушем ветки** (это и есть захват; метки — потом, как аннотация). Detached-голова и явный refspec обязательны: в общих worktree локальные ветки видны всем, а отказ пуша — единственный честный арбитр:

```sh
git fetch origin
git checkout --detach origin/main
git commit --allow-empty -m "claim: issue-#<N> [<МАРКЕР>]"
git push origin HEAD:refs/heads/agent/<я>/issue-<N>
```

- **Пуш отвергнут** (ветка уже существует) — задача уже занята кем-то, независимо от имён: молча возьми следующего кандидата. Метки не трогай, комментариев не пиши.
- **Пуш прошёл** — задача твоя: закрепи локально `git checkout -B agent/<я>/issue-<N>`, поставь аннотации: `gh label create agent:<я> 2>/dev/null`, `gh issue edit <N> --add-label agent:<я>` и комментарий `gh issue comment <N> --body "беру — <я>"`.

Подходящих задач нет — напиши «очередь пуста» и закончи.

## 3. Работа

- Ветка `agent/<я>/issue-<N>` уже создана захватом (шаг 2) от свежего `origin/main` — вместо имени ветки, указанного в issue.
- Цель — та, что описана в issue. Приёмка — аудит по смыслу после мержа, а не твои цифры.
- **Специфика репозитория:**
  - Компоненты секций — `src/components/` (подсайт «Солнышко» — `src/components/solnyshko/`), при состоянии — MobX-стор в `src/stores/` и `observer()`, данные — `src/data/`.
  - Стили — в `global.css` (основной сайт, дизайн-язык «Техдок ГОСТ») или `solnyshko.css` («Солнышко», «Советская путёвка») по принадлежности; классы — с префиксом секции, как соседние.
  - **Адаптив обязателен:** новая вёрстка работает на 390px и 1440px без горизонтального скролла (flex-элементам с инпутами — `min-width: 0`).
  - Ассеты — через `BASE_URL` (прод живёт в подпути `/urinatech/`); аватары пациентов — только ИИ-генерация по `.zcode/skills/generate-patient-photos/SKILL.md`, не реальные люди.
  - Дисклеймеры (18+, «не является лекарственным средством») не трогать.
- **Проверка перед PR:** `npm run build` зелёный. Для визуальных изменений — прогони `npm run dev` и посмотри раздел на 390px и 1440px (мобильная и десктопная ширина), опиши в PR, как проверял.
- Коммиты по-русски (конвенция репозитория), в конце тела — трейлер `Agent: <я>`. Протокольные `claim:`/`adopt:` — исключение: их формат задан арендой, без трейлера.

## 4. PR

Перед PR проверь, что задача ещё открыта и всё ещё твоя: `gh issue view <N> --json state,labels --jq '.state, [.labels[].name]'` → `OPEN` и в метках есть `agent:<я>`. Если оператор её закрыл (например, заменил другой задачей) — PR не открывай, прочитай последний комментарий в issue и закончи сессию. Если метку `agent:<я>` сняли (задачу передали другому агенту) — PR не открывай, напиши в issue, что остановился и где лежит твоя ветка, и закончи сессию.

```sh
gh pr create --base main --label agent:<я>
```

В описании: `Closes #<N>`; что сделано; допущения (спросить некого — записать, а не выдумывать молча); как проверял (сборка + просмотр на двух ширинах).

## 5. Мерж — сам

Когда CI зелёный (deploy-воркфлоу), ветка на текущем `main` (иначе — шаг 1), в PR и задаче нет просьбы исправить, на которую ты не ответил правкой (см. шаг 1), и задача всё ещё открыта и твоя (`gh issue view <N> --json state,labels --jq '.state, [.labels[].name]'` → `OPEN` и `agent:<я>`): `gh pr merge <N> --merge`. **Помни: мерж в `main` — публикация на GitHub Pages.** Задачу закрыли или передали другому агенту, пока ты работал, — не мержи, напиши в PR почему и закрой PR.

## Нельзя

- трогать `.github/`, `.zcode/`, `index.html`, `tsconfig.json`, секцию `scripts` в `package.json`;
- ослаблять типизацию, чтобы билд позеленел: `any`, `as unknown`, `@ts-ignore`, `@ts-expect-error`, правки `tsconfig.json` — запрещены всегда;
- удалять или менять на юмор дисклеймеры (18+, «не является лекарственным средством», «имеются противопоказания»);
- добавлять реальных людей, реальные клиники и фото реальных людей;
- пушить в `main`, трогать чужие ветки и issue с чужой меткой `agent:*`;
- нарушать аренду: форсить пуши (всюду, всегда), вести чужую свежую ветку, удалять чужие ветки и PR. Отвергнутый пуш — всегда «отступи», а не «продави».

Три красных CI подряд на одной и той же проблеме → объясни в PR, что не получается, сними свою метку с issue (`gh issue edit <N> --remove-label agent:<я>`) и закончи сессию.
